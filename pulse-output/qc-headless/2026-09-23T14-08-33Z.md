## 2. Gate-trail anomalies

**`draft_validate` spent its full re-roll budget (2/2)** before passing
on soft-only. Not itself an anomaly (the budget exists for this), but
worth tracking alongside the finding below since it's the same
validator script running under a different gate.

**Finding — STEP 5.75's hard-kind whitelist is missing the exact two
kinds `scripts/pulse_draft_validate.py` uses for release-figure
checks, so the gate cannot block on them regardless of severity.**
Verified by direct code reading and by re-running the validator, not
inferred from the driver log alone:

- `pulse-output/lint/2026-09-23T14-08-33Z.final-validation.json` (committed,
  produced by the live STEP 5.75 run) records `hard_count: 1,
  exit_code: 3` — one genuine hard violation (`released-actual-missing`,
  the PPI-substring bug STEP 7 diagnosed) plus a second hard instance
  (`unreconciled-release-figure`, "2.5% stated for Pce MATCHES THE
  CONSENSUS ESTIMATE").
- The driver trail's `final_validate` gate nonetheless logged
  `DECISION: CONTINUE — "no EDIT/SCRUB-introduced hard violations"` at
  14:33:43, and the pulse proceeded straight to commit.
- `scripts/pulse_driver.py:74` (`FINAL_GATE_HARD_KINDS`) hardcodes the
  only kinds this gate will ever treat as blocking:
  `duplicate-sibling-sections, contrarian-buried-in-appendix,
  main-event-lean-missing, leans-block-missing, weekday-date-mismatch,
  released-figure-mismatch, consensus-amnesia`.
- `grep`ing every `"kind"` literal `scripts/pulse_draft_validate.py`
  actually emits: `consensus-amnesia, contrarian-buried-in-appendix,
  duplicate-sibling-sections, leans-block-missing,
  main-event-lean-missing, numeric-scope-drift, released-actual-missing,
  stance-split-no-named-debate, underweighted-all-dropped,
  unreconciled-release-figure, weekday-date-mismatch`. There is no
  `released-figure-mismatch` — anywhere. `grep -rn
  "released-figure-mismatch"` across `scripts/`, `docs/`, `ai_analysis/`
  returns exactly one hit: the whitelist entry itself.
- So `released-actual-missing` and `unreconciled-release-figure` — the
  two kinds that fired hard today — are structurally absent from the
  set STEP 5.75 checks against. The gate's `new_hard` filter (line 345,
  `x.get("kind") in FINAL_GATE_HARD_KINDS`) excludes them before it
  even gets to the kind-seen-in-draft delta logic. This is not a
  today-only fluke: it means STEP 5.75 has never been able to catch an
  EDIT-introduced release-figure error, on any run, since whichever
  point `released-figure-mismatch` stopped being the validator's kind
  name for this check.
- This directly undercuts the routine's own stated purpose for STEP
  5.75 (`docs/superpowers/routines/synthesis-routine.md:1655-1657`):
  "EDIT ... the highest fact-risk operation in the pipeline ... This
  step closes that gap." For this specific check class, it does not
  close the gap — EDIT can introduce or corrupt a release-figure claim
  and nothing downstream of STEP 4.5 will ever flag it as blocking.
  `pulse_lint.py` (STEP 5.7/SCRUB) doesn't check these kinds either
  (its kind set is `section-length, slot-lean-overlap,
  slot-stat-overlap`, plus the theme-coverage checks) — there is no
  backstop between STEP 4.5 and the adversarial pre-commit checker
  (STEP 5.85), which is a different, LLM-judged, budget-capped
  mechanism, not a deterministic gate.
- I reproduced this independently: running `scripts/pulse_draft_validate.py`
  directly on the committed `pulse-output/drafts/2026-09-23T14-08-33Z.md`
  against the committed context reproduces `exit_code=4` (soft-only),
  matching the live `draft_validate` gate's logged decision exactly —
  confirming the reproduction is faithful and the divergence happens
  specifically between the DRAFT and FINAL validator runs, at the gate
  that's supposed to catch it.
- **This is separate from, and more consequential than, STEP 7's
  word-boundary diagnosis.** Fixing `_EVENT_KEYWORDS` to use `\b`
  boundaries (STEP 7's proposed fix) stops today's specific false
  positive from firing, but does nothing for the gate's ability to
  act on a *true* positive of either kind — a real EDIT-introduced
  release-figure error would sail through STEP 5.75 exactly the same
  way. Both fixes are needed: the word-boundary fix in
  `pulse_draft_validate.py`, and separately, replacing
  `"released-figure-mismatch"` in `FINAL_GATE_HARD_KINDS` with
  `"released-actual-missing"` and `"unreconciled-release-figure"` in
  `pulse_driver.py:74`.
