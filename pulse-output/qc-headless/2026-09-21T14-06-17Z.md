## Suggested fix (new, from this run)

`pulse-context/latest.json` should be frozen or copied at
pulse-generation time (or the dump job should version by run timestamp
the way every other artifact under `pulse-output/` does) so a same-day
QC pass — headless or otherwise — has a context snapshot that actually
matches the corpus the pulse was built from. Right now the file is
last-write-wins across the day's ingestion cycles, which makes it
useless for same-day verification and only reliable for next-morning QC
runs (which is probably why this wasn't caught until now — most QC runs
happen the day after, when the day's ingestion has quieted down).
