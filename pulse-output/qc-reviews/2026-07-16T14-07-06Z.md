## Issues found and fixed this run (action items for next run)

1. **CODE BUG — STITCH deletes the `_LEANS` block (TRADE BOARD source) when `_DRAFT NOTES` precedes it.** `scripts/pulse_stitch.py` strips `## _DRAFT NOTES` with `new_md = new_md[:notes_match.start()].rstrip() + '\n'` — it truncates to EOF and drops everything after the notes header, including a following `## _LEANS` block. DRAFT_USER instructs `_LEANS` to be emitted AFTER `_DRAFT NOTES`, so **any pulse that emits `_DRAFT NOTES` loses its board source**. This fired today (I emitted `_DRAFT NOTES` to record the theme fold); EDIT then reported "no `_LEANS` block in the draft" and the board would have been empty. Recovered by re-appending an accurate `_LEANS` block to `final.md` before commit (it survived STEP 5.8, which keeps `_LEANS` by design). **Fix:** change the strip to preserve the tail, e.g. `new_md[:notes_match.start()] + new_md[notes_match.end():]`, or scope the regex to a single section without truncating.

2. **Weekday regression re-introduced at EDIT.** The DRAFT validator (STEP 4.5) caught "Tuesday, July 22" (2026-07-22 is a Wednesday) and it was fixed to Wednesday. The EDIT sub-agent silently reverted it back to "Tuesday, July 22". Caught on a post-EDIT re-check and re-fixed. **Gap:** `pulse_draft_validate.py` runs pre-EDIT only; `pulse_lint.py` (post-EDIT) has no weekday-vs-date check, so an EDIT-introduced weekday error would ship. Consider porting the `weekday-date-mismatch` check into `pulse_lint.py`.

3. **`session_status` field contradicts the market snapshot.** Top-level `session_status` = "pre-market or after-hours", but `market_snapshot` says "session: OPEN (regular session)" at 09:54 EDT with session-to-date percentages. 09:54 ET is ~24 min after the 9:30 open, so OPEN is correct. Resolved by framing RECAP in OPEN young-tape mode ("about half an hour into the session"). The dumper's `session_status` computation looks stale/miscomputed and should be checked, since AUDIT_SYSTEM keys RECAP framing off that field.

4. **Context fetch transport.** `raw.githubusercontent.com/...pulse-context/latest.json` returned a clean 404 across all 3 retries (the documented dead-PAT behavior in this environment). Fetched the exact bytes via git (`git show origin/pulse-data:...`) / MCP instead. No data loss. Per the COMMIT TRANSPORT override this is expected; all commits went through the GitHub MCP.
